用户确认本轮保留通用平台能力，实施范围为胸片、皮肤镜和血细胞静态影像工作流。

具体适配规则如下。

- 账号软删除和任务归档保留研究记录与引用。超级管理员账号沿用保护策略，管理员可在个人中心修改自己的密码。
- 自定义角色在 researcher/reviewer 业务身份上配置模块授权，依赖的数据和模型模块会一并授权。
- 菜单管理调整已注册页面的名称、排序与显示，访问权限由后端独立校验。
- 多边形顶点在导入、保存、增强、切片及导出中保留。内置检测训练使用外接框，分割标签可独立导出。
- AI 预标注生成草稿，由管理员或复核员确认人工检查后冻结。派生版本冻结沿用父版本划分。
- 模型上传入口接受管理员提供的 .pt 检测权重，并核验声明的 SHA256。医学专用模型沿用各自任务契约。

验收结果和上线前提见 [验证记录](PARITY-VALIDATION-20261102.md)。

## 是否为重构代码

开发基线的运行入口为 backend/app/main.py。API 位于 app/api/v1，业务位于 domains，数据库位于 db，训练和推理由 workers、ml 承担。前端使用 api/client.js 统一鉴权及响应解包，配合 composables 和独立页面。数据保留版本、血缘、冻结、CAS revision、持久化作业机制。这些源码证明存在结构重构。

原仓库大量页面和管理能力没有等价迁入。仅凭目录分层、若依导航或构建成功，无法证明功能保真。

## 实施前页面差距的具体原因

当前 Dataset、Training、ModelHub 等页面大量使用原生 input/select/table，操作密集地排在同一行。原仓库使用 Element Plus 查询区、卡片、对话框、工具栏、详情与预览区。新增若依侧栏只覆盖外框，核心业务页面仍需按原交互重建，并将表单状态、查询分页、作业进度拆成可维护组件。

## 首批历史记录

- 新增 frontend/src/views/AdminUsers.vue 及 api/users.js，接入 /system/user 和旧 /admin/users 路径。
- API 增加用户修改和密码重置，列表可搜索分页，省略分页参数时保持原调用契约。
- 复用 User/AuthSession。账号停用、角色变更、密码重置使原会话失效。重新启用不会恢复旧会话。登录和修改通过同一用户行锁串行化。
- 管理接口要求管理员权限，路由进入时向 /auth/me 校验身份。受保护管理员账号和非法角色输入有明确错误响应。
- 首批结束时账号删除、部门绑定、动态权限、登录审计待实现，这些能力已在本轮续作补齐。管理员账户继续采用保护策略。
