## 3. 新发现的数据质量风险与处理

原 BCCD 共 364 图、4,888 框，按文件内容哈希生成 original_image 来源组，划分为 291/37/36。事后审计对全部 66,066 对图片筛查：解码 RGB 完全重复为 0，固定 dHash64 距离 <=6 找到一对跨集候选：

- `BloodImage_00037.jpg`：test。
- `BloodImage_00038.jpg`：train。
- Hamming distance=3；助手检查原图发现细胞空间布局高度一致，疑似同一视野的不同焦距照片。专业人工判定仍待补，不将助手观察写成人工审批。

该发现发生在 E1 与 E2 seed42 已使用 test 之后。文件 SHA256 不同不足以证明独立；因此已保守暂停旧协议的独立性验收。

已采取措施：

1. 停止 E2 runner，取消 seed43，保留日志、checkpoint 和历史结果；seed44 没有启动。
2. 两个旧协议目录增加独立 `BLOCKED.json`，没有修改 `config.frozen.json`。runner 会拒绝继续该协议，包括 `--retry-cancelled`。
3. 结果表状态改为 `blocked_data_quality`，图表增加风险标记。原始数值保留，不充当通过独立性验收的泛化结论。
4. 增加 `group_level=image_cluster` 和完整 `source_groups` JSON 映射导入；严格校验覆盖范围，不静默忽略映射；冻结时整组分配。
5. 准备保守分组包：364 图、363 组，将候选两图合组，图像与原标注保留。**包已准备，尚未真实导入、冻结、派生切片或开始新训练。**

详情：[数据质量说明](../../../experiments/2026-10-22/DATA-QUALITY-REVIEW.md)。筛查有局限，未发现其他候选不证明不存在其他近重复，也不能建立患者/载玻片独立性。后续重划分必须披露事后性质，不能称为从未见过的确认性 test。
