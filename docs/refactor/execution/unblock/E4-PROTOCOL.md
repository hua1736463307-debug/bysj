# E4 固定性能测量方案

登记时间：2026-10-22 08:44 America/Los_Angeles；E1 首个种子仍在训练，尚未根据正式 test 选择模型。

- 模型固定为 E1 seed=42 的 val 最佳权重，不按三 seed test 排名挑选。若该训练失败则报告阻塞，不替换成 test 最高的模型。
- 输入为已核验 BCCD manifest 中按 relative_path 排序的前 100 张 train 原图，附图像/标签 hash。测试集不进入 E4 选样。
- 只在本项目无 pending/running/cancelling 作业时执行；并发固定 1，完整 E1/E2 训练期间不测性能。
- 100 图 ZIP 导入重复 3 次，分别创建工程数据副本；记录提交 HTTP 响应与最终完成耗时，后者包含上传、排队、解析与 0.25 秒轮询误差。
- 每副本前 10 张图各保存一次现有标注，共 30 次，记录 CAS 保存耗时/错误率；不更改正式版本。
- 首份副本冻结后提交 3 个独立 1 epoch 工程训练，batch=8/imgsz=640/AdamW，记录训练提交 HTTP 耗时与 DB 领取等待。训练不做独立 test 评估，不作为 E1/E2 的新结果。
- 单图推理与 100 图批量推理各重复 3 次；每个模型句柄先做 5 张预热，预热从样本统计排除。接口上限 100，批量按 95+5 的测量样本分块，每块另加 5 预热；完整记录分块和原始 timing。
- “冷”指新模型句柄的首次推理，不代表 OS 缓存清除或机器重启。批量吞吐明确包含预热和提交/完成轮询；同时给出排除预热的图像处理耗时分布，不混用两种口径。
- 宿主 nvidia-smi 采样设备显存/利用率；受控容器 /proc 采样 API/dataset/trainer/inference 进程 RSS 总和。记录每次采样时间与失败，采样峰值是下界，RSS 可能重复计算共享页，设备显存包含显示进程。
- 输出原始逐次记录、n/p50/p95/max、失败率、吞吐、队列/GPU 等待和资源峰值。n=3 的分位数仅为描述统计，不声称总体尾延迟。

实现：scripts/benchmark_workflow.py（调用已有 benchmark_medical.py）。4 项输入边界测试已通过，实际测量仍待 E1/E2 队列结束。冻结文件保存在 artifacts 下专属 SHA256 目录，重测新建执行时间戳，不覆盖旧测量。
