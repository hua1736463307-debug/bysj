## 3. 本轮由实测发现并修复的两个真实缺陷

单元测试（dummy 后端）无法暴露，只有在真 torch + GPU 下才出现：

1. **`device="0"` 被直接传给 torch** → `RuntimeError: Invalid device string: '0'`。
   `CxrTrainingParams.device` 默认 `"0"`（沿用 detect 习惯），但 torch 只接受 `cuda:0`/`cpu`。
   修复：新增 `_normalize_device()`，把裸序号、`cuda`、越界序号统一归一化，无 CUDA 时回退 cpu；
   并加单测 `test_device_string_is_normalized_for_torch`。
2. **Grad-CAM 目标层与 DenseNet 的原地 ReLU 冲突** → `RuntimeError: Output 0 of
   BackwardHookFunctionBackward is a view and is being modified inplace`。
   `DenseNet.forward` 在 `features.norm5` 之后执行 `F.relu(features, inplace=True)`。
   修复：目标层改为 `features.denseblock4`（输出经 BatchNorm 消费，不原地改），
   改用 forward hook + tensor `register_hook` 取梯度。
3. **退化热图静默输出全零**：随机/弱模型下加权和可能全为非正，ReLU 后整图为 0，
   归一化后变成一张全黑图。修复：`normalize_cam()` 在峰值≈0 或含非有限值时抛
   `409 cxr_explain_degenerate`，`run_explanation` 把原因写入
   `analysis.explanation_json.failures[label_key]`，热力图保持 null；
   评分与结构化报告不受影响。实测 5 标签中确实出现 1 例，证明该分支是必要而非防御性摆设。

## 4. 要把 CXR 跑到真实数据还缺什么

按 M00/M10 门禁，顺序不可跳：

1. **备份**：当前无在途作业、`gpu:0` 空闲 → 满足备份前置条件；
   执行 `scripts/backup_project.py --project bysj-restore2-20261022 --helper-image <实际API镜像ID>`。
2. **构建新镜像**：从干净提交（`672f2d2` 或之后）构建 api/worker，标签需带精确 SHA；
   worker 需带上新代码（CXR 模块），API 保持无 torch。
3. **迁移**：`alembic upgrade head`（`f002 → f003`），先在副本验证，再对正式库执行。
4. **重启并复查健康**，失败只回切本次镜像，不回灌旧 DB。
5. **数据**：仍需 `CXR_IMPORT_ROOT` 指向已授权的 CheXpert 副本（当前 **BLOCKED_REAL_DATA**）。
6. 之后才是真实 2 epoch smoke → 校准 → 一次 test 评价。

本轮**未执行** 1–4：构建 10GB 级镜像、迁移正式库、重启服务均属改变运行态的操作，
需要单独确认；且第 5 步仍未满足，即使上线也只能跑合成 fixture。
