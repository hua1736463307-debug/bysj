# 后续重构顺序

1. 将单体 `yolo_api.py` 按数据集、标注、训练、模型、推理、鉴权拆成独立 router/service。保持当前回归测试作为边界。
2. 从入口导入、路由注册、启动钩子、数据库种子和依赖列表中逐项解除行为告警、人脸、监控、录机及外部推送；解除后删除对应耦合保留代码。
3. 统一配置与路径，移除固定 `/app` 和运行目录假设；独立数据库与模型/数据路径不得引用原生产服务。当前训练 worker 使用 PostgreSQL advisory lock，SQLite 测试不能替代 worker 运行验收。
4. 按新任务替换 phone/badge 等原业务类别、默认配置及标签，收敛页面和 API 契约；明确是否保留姿态训练备用组件。
5. 确定公开数据集与许可，记录样本来源、原图/病例分组和固定划分；建立基线与独立测试集。
6. 固定依赖和可复现环境，完成全新安装、数据库初始化、登录、导入、标注、训练、指标查看、推理的端到端演示，再开展所选任务的对比实验。

不从原服务器迁移数据库、模型或数据。不合并原仓库未发布的安全修复分支；如需复用其修复，另做窄范围审查与迁移。
