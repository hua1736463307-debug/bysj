# 筛选范围与毕设定位

用户授权：暂未确定题目和保留功能，由现有仓库选取适当范围，为后续重构保留必要代码。既有讨论明确希望基于当前平台重构且不使用公司数据。

| 层级 | 选择 | 用途 |
|---|---|---|
| 核心前端 | Dataset、Annotation、DatasetManager、Training、ModelHub、Inference | 数据到训练、推理的演示链路 |
| 核心后端 | 数据集版本、标注草稿、增强、导出、YOLO/YOLOE 训练、模型和任务模块 | 可复用实现与回归依据 |
| 支撑 | 鉴权、数据库模型、日志、GPU/任务调度、组件及工具的导入闭包 | 避免复制页面后缺依赖 |
| 耦合保留 | yolo_api 的行为、姿态、人脸、告警、录机及监控模块依赖 | 暂时维持入口可导入；不是毕设承诺功能 |
| 排除 | 生产 Compose、ops/scripts、runtime-sources、监控/告警/系统管理页面、旧哈希模板 | 与当前核心范围无关 |
| 排除数据 | 公司数据、模型、用户、环境文件、现网 GPU profile 和运行输出 | 新项目仅使用单独获取的合规公开或自建数据 |

目前是检测、标注与训练工具链，不是疾病诊断系统，也未实现医学任务专用算法、DICOM 工作流或临床评价。后续先确定公开数据集、标注类型、任务及评估方案，再决定是否转向具体医学图像题目。必须按原始图像/病例分组隔离训练、验证和测试，避免增强/切片同源样本跨集合。

选取清单中的 `reason` 表示保留原因；`source_sha256` 和 `selected_sha256` 区分原始代码与本次适配。代码中尚有通用物体类别和原业务语义，需在后续重构中按新任务修改，不能直接当作医学语义。
